Three rules that never bend

1Read only

The reviewers hold an API key with read scopes only. The barrier is the key, not the prompt. Zero write tools exposed.

2No finding without evidence

Every finding points to voucher numbers, amounts, dates and documents the tools actually returned. If the evidence is not there, the finding is not there.

3Never intent

We describe the deviation, the pattern it deviates from, and the evidence. Judging people is for people.

The loop

one stepone sessiongreencommitone line in the lognew session

Spec before build for anything bigger than one step: brainstorm without code, spec with every assumption marked, a plan where each step is verifiable and touches at most three files, review by a read-only reviewer, the owner decides, then build. Every check carries a false-alarm guard: what must be verified before it may fire. False alarms are what cost trust.

Roles

  • Analysis qwen3.6 on Staik: investigates, calls the tools, formulates findings with evidence.
  • Control and language gemma4 on Staik: tests each finding against its evidence and writes the Swedish report. A deterministic gate stops anything containing foreign scripts or intent words.
  • Reviewer a read-only agent that reviews every diff before merge.
  • The humans pick checks, read specs, approve, own the demo and the domain.

Done means

  • The scorer reports a hit on the planted error the check was built for.
  • No alarm on the controls: the group loan and the kick-off coffee with a participant list must pass silently.
  • Clean Swedish for the end user, English as a toggle, no other scripts.
  • PR against upper-hand, one owner merges. Tests are run, never claimed.
